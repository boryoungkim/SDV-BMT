DUT-service = t_complete - t_submit_begin includes H2D + native runtime/graph + D2H.
Output stage = t_output_ready - t_complete includes checked u8 conversion + common
postprocess/encode/record. Request completion/output_ready also include issue lag
from t_sched. Never subtract overhead to re-label metrics.

Synchronous fallback is common §6.3, NOT asynchronous completion. Issuer/timeout/
arrivals are serviced after submit returns. Must be disclosed before real capture.
Common §6.4 permits output conversion in collect; device guide's ideal output is
uint8 from the model/device, so explicitly confirm this location with maintainer.
The R18 actual trial was a cold, unqualified direct-graph run; it includes first-use
JIT and allocation and is not pure NPU latency or steady-state throughput. It passed
for one image only. No current evidence proves full native steady-state resource
behavior; dataset qualification and prebuilt buffer/trace reuse must be measured
first. R50 and R101 have not run through the native SDV-BMT executor on the NPU.
Standalone Python R101 success is not native executor qualification. R101 uses the
BF16 branch, but its larger-channel memory/tile behavior still needs bounded gates.
