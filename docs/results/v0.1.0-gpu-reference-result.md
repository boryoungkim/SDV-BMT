# GPU reference result — SDV-BMT v0.1.0

> Research benchmark result on a **reference accelerator** (an NVIDIA GPU), not an NPU result and not a GPU
> ranking. Percentiles characterize the measured distribution; `max_observed` is the largest observed value in
> that population, not WCET. Deadlines are evaluation parameters, not FTTI. Nothing here establishes ISO/PAS 8800,
> ISO 26262 or SOTIF compliance or vehicle-level safety.

This page summarizes the evidence behind the v0.1.0 reference result. The raw evidence bundles are not part of
the repository (they contain host-local details); every number below was taken from them by the tools in
`tools/metric_set_v1/` and `tools/stage2b_g_real/`.

The host was shared: 10 logged-in sessions and a 1-minute load average of 43.4 on 64 logical CPUs immediately before the run. ## 2. Earlier Metric Set v1 run (pre-release code, foreign GPU context)

Same plan and configuration as section 1, recorded before the release hardening with pre-release code, i.e. before the native timeout-ordering fix. The fix changes a recorded outcome only when a timeout or the next arrival is already due when a completion is observed; that did not occur in this run (every completion was observed at most 7.03 ms after its submit, against a 1 s timeout, and at least 26.3 ms before the next arrival). **A foreign compute process was detected on the GPU** at both measurement-window edges (another user's idle context; no non-zero utilization samples from other processes). The bundle records this as observed `competing_device_users` evidence, and the Realization Guard therefore refuses to compare this run with runs recorded without it (section 5). ## 4. Task quality and numerical correctness

- Canonical COCO evaluation (`coco-detection-bbox/1`) from the ground truth frozen in the bundle equals the
  analysis-plane evaluation of the same outputs against the digest-verified dataset index on all nine reported
  statistics and the coverage.
- The SDV-BMT evaluator re-implements the pycocotools `COCOeval` (bbox) algorithm; on the baseline outputs it agreed
  with pycocotools 2.0.11 within 7.55e-15 (per-category AP within 7.22e-15) over the 12 standard statistics.
- Numerical correctness (offline diagnostic, not a catalog metric): raw GPU outputs vs ONNX Runtime 1.19.2 on CPU,
  largest per-image absolute difference over 1,000 images x, y 2.1e-04; log w, log h 2.6e-04; objectness 2.4e-05; class scores 3.9e-05; all 36,170 (GPU) / 36,170 (ONNX Runtime) detections matched one to
  one; COCO AP of the ONNX Runtime outputs 0.4289194027422574 vs 0.4289194068359202 on the GPU (difference 4.09e-09).
- Output identity (`bmt.output.identity_rate`) compares output digests with a reference captured before the run on
  the same GPU; it is a determinism / corruption diagnostic, not evidence of correctness.

## 6. Limitations

- One GPU, one model, FP32, batch 1, N = 1, a 1,000-image subset of COCO val2017; not optimized (no TensorRT, no
  CUDA graphs, no reduced precision).
- Shared host: tail latencies can include other users' load; host preemption and CPU frequency were not observed.
- DUT service includes host enqueue of 176 device operations per request, device execution and completion
  observation; the CUDA-event device-execution bracket can include waiting for host enqueue and is not device
  busy time.
- The canonical run is a single run; run-to-run variation is shown by section 3 only.
