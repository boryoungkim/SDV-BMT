# SDV-BMT v0.1.0 — release notes

**SDV-BMT v0.1.0 — Model-level Accelerator Benchmark Core.** First public release of a research benchmark
framework that records how a Model-level accelerator measurement was planned, realized and measured, evaluates
it from that evidence alone, and refuses to attribute differences that the evidence does not isolate.

Release date: 2026-10-09. License: Apache-2.0 ([`LICENSE`](../../LICENSE)). Citation: Boryoung Kim,
[`CITATION.cff`](../../CITATION.cff).

> SDV-BMT v0.1 is a research benchmark framework. Its Model-level measurements do not establish WCET, FTTI,
> ISO/PAS 8800 compliance, ISO 26262 compliance, SOTIF compliance, or vehicle-level safety. Percentile latency is
> distribution characterization, not a worst-case timing guarantee. `max_observed` is not WCET.

## What is in v0.1.0

- **Deterministic Model-level core**: typed dataset and recorded-scenario inputs, deterministic replay (fixed
  rate, recorded, asap), N = 1 / queue 0 / `drop_new` admission, timeouts with late completion, append-only
  evidence bundles, bundle-only evaluation, golden regression cases.
- **Native realtime measurement plane** (C++): single-threaded spin issuer on the host monotonic clock, phase
  protocol with the Python control plane, per-request facts written after the measurement window; no metric is
  computed natively.
- **NVIDIA GPU reference backend**: CUDA event brackets (H2D / device execution / D2H), NVRTC kernels, a cuDNN plan
  executor with pinned algorithm tables, NVML window snapshots, realization evidence; an optional Nsight Systems
  cross-check configuration. The GPU is a reference accelerator, not the NPU target.
- **Real-model reference workload**: YOLOX-S (official ONNX → offline cuDNN plan) on the first 1,000 COCO val2017
  images.
- **Model-level Metric Set v1**: 91 metrics in five layers (performance, timeliness, task quality, diagnostics,
  validity / evidence), each with its population context; canonical COCO detection quality from a ground truth
  frozen in the bundle; the earlier Stage 1A catalog stays available and reproduces earlier evaluations byte for
  byte.
- **Contrast validity**: Design, Realization and Measurement Guards; no attribution without validated factor
  isolation.

## Release hardening since the internal baseline

- **Fixed — realtime timeout ordering.** The native loop now decides already-due events by their semantic
  timestamps (arrival `t_sched`, timeout `t_submit_begin + request_timeout_ns`, completion `t_complete`); the
  completion → timeout → arrival tie order applies only to equal timestamps. A loop that wakes after a timeout was
  due now records TIMED_OUT followed by a late completion (previously COMPLETED), and an arrival due before a
  late-observed completion finds the slot held. Deterministic C++ tests reproduce delayed loop observation with a
  simulated clock; they fail against the previous loop (176 failed checks) and pass with the fix.
- **Added — evidence check** `completed_beyond_request_timeout` in Metric Set v1 evaluations: flags COMPLETED
  requests whose service exceeded the configured timeout (possible in bundles recorded before the fix); it never
  changes recorded states or metric values.
- **Added** — `make -C native portable`, a CPU / portable GitHub Actions workflow, `LICENSE` (Apache-2.0),
  `README.md`, `THIRD_PARTY_NOTICES.md`, `CITATION.cff`, a public result summary (`docs/results/`).
- **Changed** — version 0.1.0 (`sdv-bmt --version`); host-local dataset paths removed from public configs and
  tools.

## Reference result

On one NVIDIA RTX PRO 6000 Blackwell GPU (reference accelerator), YOLOX-S on the first 1,000 COCO val2017 images at 30 Hz, N = 1: DUT-service p50 / p99 / max_observed 4,874.4 / 6,397.0 / 7,634.3 µs, no drops or deadline misses, COCO AP 0.42892 from the ground truth frozen in the bundle (equal to the independently cross-checked evaluation). Replicate and cross-condition comparisons stay non-attributable (Realization Guard unresolved or failed).

Full summary, setup and limitations: [`docs/results/v0.1.0-gpu-reference-result.md`](../results/v0.1.0-gpu-reference-result.md).

## Compatibility

- Evidence bundles: manifest v3 (Stage 1A virtual), v4 (realtime), v5 (realtime with frozen task-quality
  reference). Older bundles are read, never reinterpreted.
- Version labels: bundles recorded during development keep the internal label of their time (`0.1.0` in
  Stage 1A bundles, `0.2.0` from Stage 1R on); `code_identity.source_tree_sha256`, not the version string,
  identifies the code that produced a bundle.
- Evaluations: schema 1 (legacy catalog, frozen format) and schema 2 (Metric Set v1). `--catalog
  bmt-portable-v1-stage1a` reproduces legacy evaluations.
- Python ≥ 3.10; runtime dependency PyYAML only. Native: g++ (C++17) and make; the NVIDIA runner additionally
  needs CUDA 13.0 headers / NVRTC / driver and cuDNN 9.

## Not included

NPU integration, Driving Scenario stage, hardware stress sweep, Scenario × Stress matrix, Autoware /
system-level evaluation, WCET or FTTI claims, functional-safety compliance claims, a canonical calibration
formula, energy per inference, a DRAM-bandwidth metric, AI error rates per hour or km, TTC / PET / DST, SPFM /
LFM / PMHF / FIT.

## Known limitations

- One reference GPU, one model (FP32, batch 1), N = 1; the GPU path is not optimized for speed.
- The reference host is shared; tail latencies can include other users' load, and host preemption is not observed.
- Seven realized conditions stay unresolved for replicate pairs (no approved continuous equivalence rules,
  self-reported residency and buffer state, no hardware counters for memory bandwidth, nominal stress not checked),
  so no measured difference is attributable to a factor in this release.
