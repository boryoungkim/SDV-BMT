# SDV-BMT v0.1.2 — release notes

**SDV-BMT v0.1.2 — model extension on the GPU reference track.** The measurement core of v0.1.0 now runs eight
reference models instead of one: five YOLOX object detectors on COCO and three DeepLabV3+ semantic segmenters on
Cityscapes. Segmentation quality is part of the metric catalog, and stricter checks run before a run starts.

Release date: 2026-11-10. License: Apache-2.0 ([`LICENSE`](../../LICENSE)).

> SDV-BMT v0.1 is a research benchmark framework. Its Model-level measurements do not establish WCET, FTTI,
> ISO/PAS 8800 compliance, ISO 26262 compliance, SOTIF compliance, or vehicle-level safety. Percentile latency is
> distribution characterization, not a worst-case timing guarantee. `max_observed` is not WCET. GPU results are
> reference-accelerator results, not NPU results.

## What is new in v0.1.2

- **YOLOX family**: YOLOX-Tiny (416 × 416), M, L and X next to YOLOX-S (official ONNX models, YOLOX 0.1.1rc0).
  The workload declares its input size and anchor count; the plan converter accepts S × S inputs.
- **Semantic segmentation**: DeepLabV3+ ResNet-18/50/101-D8 (mmsegmentation Cityscapes checkpoints) on full
  2048 × 1024 Cityscapes val images. The GPU returns a uint8 label map, recorded losslessly with the
  `labelmap-u8-rowrle/1` codec; the native output stage and its Python twin produce identical bytes.
- **Model-level Metric Set v1.1** (new default): Metric Set v1 unchanged plus `quality.segmentation.coverage` and
  `quality.segmentation.conditional.miou`, computed from the ground truth frozen in the bundle. The mIoU equals the
  official cityscapesScripts evaluation.
- **Native cuDNN plan operations** for DeepLab (ReLU after residual add, global average pool, broadcast, bilinear
  resize, uint8 argmax), compiled only when a plan uses them.
- **Checks before a run starts**: fixed-rate deadline vs rate, input preprocessing contract vs workload contract,
  native runner build stamp vs native sources, cuDNN plan buffer ranges and full task-output coverage, timing
  offset alignment. A mismatch is rejected before anything is measured.
- **Tools** for model conversion, numeric gates, official cross-checks, the Cityscapes val builder, the
  replay-rate rule and experiment generation (`tools/yolox_family/`, `tools/deeplab_family/`).

## Behavior changes

- `sdv-bmt evaluate` uses Metric Set v1.1 by default. On detection bundles the 91 v1 metrics have the same
  values; the catalog identity differs, so the Measurement Guard does not pair v1.1 and v1 evaluations. Use
  `--catalog sdv-bmt-model-metric-set-v1` to reproduce v0.1.0 evaluations byte for byte.
- Plans that v0.1.0 accepted can be rejected by the new start-up checks (details in [`CHANGELOG.md`](../../CHANGELOG.md)).
  In particular, rebuild the native runner (`make -C native` or `make -C native portable`) after any change under
  `native/`, and declare an input preprocessing contract that matches the workload.

## Reference results

On one NVIDIA RTX PRO 6000 Blackwell GPU (reference accelerator), FP32, batch 1, N = 1, five fixed-rate runs per
model; ranges are min–max over the five runs:

| model | data | rate | DUT-service p50 (ms) | drops / deadline misses | quality |
|---|---|---|---:|---|---|
| YOLOX-Tiny | COCO val2017, first 1,000 | 30 Hz | 2.23–2.30 | 0 / 0 | AP 0.3437 |
| YOLOX-S | COCO val2017, first 1,000 | 30 Hz | 4.36–4.38 | 0 / 0 | AP 0.4289 |
| YOLOX-M | COCO val2017, first 1,000 | 30 Hz | 9.75–10.57 | 0 / 0 | AP 0.4948 |
| YOLOX-L | COCO val2017, first 1,000 | 30 Hz | 16.18–16.22 | 0 / 0 | AP 0.5294 |
| YOLOX-X | COCO val2017, first 1,000 | 30 Hz | 26.76–28.06 | 0 / 0 | AP 0.5327 |
| DeepLabV3+ R-18 | Cityscapes val, 500 | 2 Hz | 25.51–25.86 | 0 / 0 | mIoU 0.7676 |
| DeepLabV3+ R-50 | Cityscapes val, 500 | 2 Hz | 114.27–114.76 | 0 / 0 | mIoU 0.7985 |
| DeepLabV3+ R-101 | Cityscapes val, 500 | 2 Hz | 165.64–166.45 | 0 / 0 | mIoU 0.8087 |

YOLOX-S reproduces the v0.1.0 result (AP 0.4289194068359202, byte-identical outputs). The GPU outputs agree with
ONNX Runtime (AP within 4.4e-7; mIoU within 1e-7), and the DeepLab mIoU is within 0.003 of the mmsegmentation model
zoo. Models are compared side by side; differences between models are not attributed to a cause.

Full summary, setup and limitations: [`docs/results/v0.1.2-gpu-reference-result.md`](../results/v0.1.2-gpu-reference-result.md).

## Compatibility

- Evidence bundles: manifest v3, v4 and v5 as in v0.1.0; segmentation bundles use manifest v5 with the frozen
  label-map ground truth. Older bundles are read, never reinterpreted.
- Evaluations: schema 2 for Metric Set v1 and v1.1; schema 1 for the legacy catalog (`--catalog
  bmt-portable-v1-stage1a`).
- Version labels: the v0.1.2 evidence bundles were recorded while the package version was 0.1.0 and keep that
  label; `code_identity`, not the version string, identifies the code that produced a bundle. There is no 0.1.1.
- Python ≥ 3.10; runtime dependency PyYAML only. Native: g++ (C++17) and make; the NVIDIA runner additionally
  needs CUDA 13.0 headers / NVRTC / driver and cuDNN 9.
- No model files, COCO or Cityscapes images or annotations are included. Cityscapes data is used under its own
  terms (registration, no redistribution); see [`THIRD_PARTY_NOTICES.md`](../../THIRD_PARTY_NOTICES.md).

## Not included

Everything listed as not included in v0.1.0 (NPU integration, driving scenarios, stress sweeps, system-level
evaluation, WCET / FTTI and functional-safety claims, among others), and: other precisions or batch sizes,
contrast designs that attribute differences between models, and the measurement extensions planned for v0.2.

## Known limitations

- One reference GPU, FP32, batch 1, N = 1, one replay rate per model family; the GPU path is not optimized for
  speed.
- The reference host is shared; host load is logged only between runs, and host preemption is not observed. The
  GPU was power-cap limited during the DeepLab runs.
- The cuDNN math type is the default; whether TF32 was used is not observed.
- Each family was measured on one day, with the code of its stage; the runs were not repeated with the release
  code (see the result summary).
