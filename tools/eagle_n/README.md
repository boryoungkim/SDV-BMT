# DeepLabV3+ on the Eagle-N NPU: reproduction

How to rebuild and rerun the Eagle-N port of DeepLabV3+ R-18 through SDV-BMT, from the ONNX model to the baseline
runs. Only R-18 is configured for Eagle-N; R-50 and R-101 run on the GPU. The porting tools (`export_plan.py`,
`decompose_proven.py`, the L1 tools) still accept the R-50 and R-101 plans, but no Eagle-N config is shipped for them. What the port is and why it is built this way: `docs/eagle_n/eagle-n-deeplab-port.md`.
**No measurement results on this page**; they stay in the evidence root.

| Model | DUT config | Workload | Capture plan | Baseline plan |
|---|---|---|---|---|
| R-18 | `eagle-n-r18.yaml` | `deeplabv3plus-r18-cityscapes-v1-eagle-n.yaml` | `deeplabv3plus-r18-eagle-n-capture.yaml` | `deeplabv3plus-r18-eagle-n-baseline.yaml` |

They are generated by `configure.py` (step 3); do not edit them by hand.

## Requirements

| component | version used | note |
|---|---|---|
| Eagle-N A0 board, BOS kernel driver | device node `/dev/bos/0` | |
| BOS container image | `sha256:bb29c5af20279d1ad95805ebfb2061399d409778b3ba54d87b1f102235d6ec8d` (pinned in `in_container.py`) | every device step, build and SDV-BMT command runs inside it |
| BOS SDK (TT-Metal / TTNN) | commit `6878560cb7dbd8cbef9be01868b7e40424a37308`, `build_Release_distributed` | `EAGLE_N_SDK_ROOT`; mounted read-only; library SHA-256s recorded in `<executor>.sdk.json` and checked by the adapter |
| 1 GiB hugepages | at least 1 free page in the existing pool | the launcher mounts a private hugetlbfs; it never changes the system reservation |
| repo `.venv` | Python 3.11 | also used inside the container |
| ONNX Runtime (L1 reference only) | 1.19.2, CPU | a separate read-only Python, `EAGLE_N_ORT_PYTHON` |
| Host resources | several GiB of free disk on the evidence file system and of RAM for one run | run nothing heavy on the host during a device run |

Inputs are prepared as for the GPU reference (repository README): the DeepLabV3+ R-18 ONNX file and the
`datasets/cityscapes-val500` index.

## Host setup (once per host, by the operator)

The configs and tools name the Eagle-N files under one fixed root, `/opt/sdv_assets/eagle_n`, so they are the same
on every host. Point it to the directory that holds the Eagle-N files:

```
sudo mkdir -p /opt/sdv_assets
sudo ln -sfn <eagle-n root on this host> /opt/sdv_assets/eagle_n
export EAGLE_N_SDK_ROOT=<BOS SDK root>          # e.g. a TT-Metal checkout with build_Release_distributed
export EAGLE_N_ORT_PYTHON=<python with onnxruntime and numpy>   # L1 reference only
```

Layout under the root (`$R` = `/opt/sdv_assets/eagle_n`):

| path | content | pinned by |
|---|---|---|
| `$R/eagle_n_integration_assets/libeagle_n_ttnn.so` | the executor, with `.build.json` (build record) and `.sdk.json` next to it | `executor_sha256` and `executor_source_sha256` in every DUT config and in the receipts |
| `$R/eagle_n_integration_assets/r18/` | `<model>.plan.json`, `<model>.weights.f32`, `compile_record.json`, `native_qualification.json` (receipt) | plan, weights and record SHA-256 and `qualification_sha256` in the workload |
| `$R/eagle_n_integration_assets/kernel_cache_<model>` | TT-Metal JIT kernel cache, reused across runs | not pinned; an empty cache only makes prepare slower |
| `$R/eagle_n_integration_assets/r18_trial/input.ppm`, `$R/eagle_n_porting/deeplab_<model>/` | L0 golden images and their ONNX Runtime labels, ONNX files for the L1 reference | SHA-256 in `l1_native.py` and `l1_ort.py` |
| `$R/eagle_n_integration_evidence/` | evidence root (`EAGLE_N_EVIDENCE`): one directory per launcher call and `COMMANDS.log` | |

The launcher (`in_container.py`) mounts the root at both its real path and `/opt/sdv_assets/eagle_n`, the repository
checkout at its own path and the SDK read-only. It uses `sudo -n` for Docker, the private hugepage mount and the NPU
user check: run `sudo -v` before a step that starts a container.

## Steps

`<m>` = `r18`; `$A` = `$R/eagle_n_integration_assets`; `$E` = the evidence root. Run every command
from the repository root. **Device** = the step uses the NPU: one at a time, NPU idle, no heavy host process.

| # | step | where | command | device |
|---|---|---|---|---|
| 1 | Build the executor and the runner | container | `python3 tools/eagle_n/in_container.py build` (writes the executor with its build record and SDK identity, and the runner) | no |
| 2 | Export the plan (once per model) | host, repo `.venv` | `python3 tools/eagle_n/export_plan.py --variant r18 --onnx <onnx> --out $A/r18` | no |
| 3 | Generate the configs | host | `taskset -c <cpus> python3 tools/eagle_n/configure.py` (the CPU affinity of this process becomes the plans' `cpu_affinity`) | no |
| 4 | L0 safety gates for a new or changed plan: L1-memory preflight and proven-shape survey | container + host | `python3 tools/eagle_n/in_container.py l1 0:0 --preflight --dut <dut> --workload <workload> --kernel-cache $A/kernel_cache_<m>`, then `python3 tools/eagle_n/proven_survey.py --candidate <preflight.json> --proven <preflight.json of plans that already ran> --out <survey.json>` | no |
| 5 | L0: one golden image, several identical trace replays | container | `python3 tools/eagle_n/in_container.py l1 0:0 --dut <dut> --workload <workload> --kernel-cache $A/kernel_cache_<m>` | **yes** |
| 6 | L1: val500 on the NPU in two parts, merged | container + host | `in_container.py l1 0:250 …` and `in_container.py l1 250:250 …` (same options as step 5), then `python3 tools/eagle_n/l1_merge.py <part1>/l1 <part2>/l1 --out $E/l1_merged_<m>_<stamp>` | **yes** |
| 7 | L1: ONNX Runtime FP32 reference | host CPU | `VARIANT=<m> NPU_DIRS="<part1>/l1 <part2>/l1" NPU_MIOU=<merged NPU mIoU> tools/eagle_n/run_l1_ort.sh` | no (CPU heavy) |
| 8 | Qualification receipt | host | `python3 tools/eagle_n/qualify_native.py --dut <dut> --workload <workload> --l1-npu <l1_merged dir> --l1-ort <l1_ort dir>` (add `--replace` to replace an old receipt; it is backed up) | no |
| 9 | Pin the receipt | host | rerun step 3: `qualification_sha256` is now set in the workload | no |
| 10 | L2: describe + validate | container | `tools/eagle_n/run_eagle_n.sh <m> l2` | no |
| 11 | L3: capture (asap) + evaluate; mIoU must equal L1; the golden must equal the committed one | container | `tools/eagle_n/run_eagle_n.sh <m> l3` | **yes** |
| 12 | L4: second capture, identity 1.0 against the committed golden | container | `tools/eagle_n/run_eagle_n.sh <m> l4` | **yes** |
| 13 | L5: baselines | container | `tools/eagle_n/run_eagle_n.sh <m> l5` (`L5_RUNS`, `L5_START=k` to continue after a reviewed stop) | **yes** |

`tools/eagle_n/run_eagle_n.sh <m> check` runs the host checks of steps 10–13 without Docker or device: receipt,
artifacts, executor source and runner stamp consistent, capture plan asap, golden present, and the expected mIoU
taken from the receipt.

A new model or a changed plan has no committed golden yet: after step 11, copy `<run>/capture.golden.jsonl` to
`configs/references/…eagle-n…-capture.golden.jsonl` (only with the maintainer's approval) and rerun step 3.

## Checks that must hold

- **Steps 4–5:** the preflight reports no op over the L1 bank size; the survey finds no unproven SDK call; the golden
  replays give identical labels and agree with ONNX Runtime FP32 above the internal floor.
- **Steps 6–8:** the receipt is issued only when the L1 NPU mIoU is at most 0.01 below the GPU FP32 mIoU (accuracy
  criterion) and close to the ONNX Runtime mIoU (sanity bound). It binds the executor, its source digest, the plan,
  weights and index to that evidence.
- **Step 11:** every item completed, none timed out or failed, and the evaluate mIoU equals the L1 NPU mIoU in the
  receipt exactly (`CHECK_OK`); the re-extracted golden is identical to the committed one.
- **Step 12:** identity rate 1.0 against the committed golden (`IDENTITY_OK`).
- **Step 13:** every run: no timeout or error and identity 1.0 for the completed outputs. The baseline replays the
  Eagle-N rate of the model (`BASELINE_RATE_HZ` in `configure.py`: the GPU family rule applied to the Eagle-N
  capture), so dropped requests and deadline misses are reported results, not failures.

## Safety rules

- New or changed plans reach the NPU only after step 4 passes.
- Nothing is retried automatically. The first failure stops the scripts; review before rerunning.
- Never kill a process or container that holds the NPU. If the board stops answering, report it; on the reference
  host only a host reboot recovered it.
- Any rebuild of the executor requires steps 5–9 again for every model. Rebuilding only the runner
  (`make -C native eagle-n` or `in_container.py build-runner`) does not, and is required whenever `native/` changes.

## Tools in this directory

| file | purpose |
|---|---|
| `run_eagle_n.sh` | L2–L5 for one model through SDV-BMT (`check`, `l2`, `l3`, `l4`, `l5`) |
| `eagle_n_checks.py` | host checks used by `run_eagle_n.sh`: pins, receipt, executor source, result and identity checks |
| `in_container.py` | launcher: every Docker step (`build`, `build-runner`, `describe`, `validate`, `run`, `evaluate`, `l1`), receipt and staging prechecks, private hugepage mount; never kills a container that holds the NPU |
| `build_native.sh`, `build_runner.sh` | executor (with build record) and runner builds inside the container |
| `sdk_identity.py` | SDK commit and library SHA-256s next to the executor |
| `export_plan.py` | ONNX (H04-checked) → device plan + constants; `--graph tuned` uses `decompose_proven.py` |
| `decompose_proven.py` | rewrites layer4 and the head of R-50/R-101 into blocks of proven shapes |
| `proven_survey.py` | proven-shape survey of every SDK call of a plan against plans that already ran |
| `configure.py` | every Eagle-N DUT, workload and experiment config |
| `l1_native.py`, `l1_merge.py` | L0/L1 on the NPU (inside the container) and the exact merge of the parts |
| `l1_ort.py`, `run_l1_ort.sh` | L1 ONNX Runtime FP32 reference on the CPU |
| `qualify_native.py` | qualification receipt from the L1 evidence |
